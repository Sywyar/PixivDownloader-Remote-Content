emSign 证书信任风险

v1.14.2 及以前版本的用户请立即更新至 v1.14.3 及以上，降低出站 HTTPS 通信被劫持及 Cookie 等敏感数据泄露的风险。

影响范围

v1.14.2 及以前版本的用户均应升级。使用仍信任受影响证书链的 Java 运行时或信任库时，程序的出站 TLS/HTTPS 通信存在风险，包括 Windows 安装包和便携包的内置 Java。自备 Java 或自定义信任库也需要单独检查。

安全风险

eMudhra / emSign 的部分中间 CA 私钥过弱，攻击者可据此为任意网站伪造受信任的证书。只要攻击者能够拦截流量，所有使用受影响信任库的出站 HTTPS 连接都可能被劫持、监听或篡改，不限于原本使用 emSign 证书的网站。

这可能泄露请求中携带的 Cookie、访问令牌、API Key 及用户内容，进而危及账号安全。浏览器、系统组件或外部工具使用各自的信任机制，需要分别判断；此风险不代表所有协议或每次连接都已被攻破，也不等于本地保存的数据已被直接读取。

请立即更新

请您务必马上通过项目 Release 发布页、软件内置“检查更新”等入口，将程序更新至 v1.14.3 及以上，并完成安装、重启程序，以保护程序保存并在联网请求中使用的 Cookie 等敏感数据。

v1.14.3 的 Windows 安装包和含内置 Java 的便携包移除了 emSign ECC Root CA - G3 信任根，并增加问题证书链检查。依赖该根的正常 HTTPS 服务也会不再受信任。使用 Java ZIP、自备 Java 或自定义 trustStore 的用户，还须更新实际使用的运行时或信任库；仅替换程序 JAR、更新系统 Java 或 Windows 证书库，不能替代内置运行时更新。

更新完成前请暂停涉及敏感数据的联网操作，不要关闭证书或主机名验证。如果怀疑 Cookie 等凭据已泄露，应在对应服务中撤销会话或凭据并重新获取；更新程序无法收回已经泄露的数据。
