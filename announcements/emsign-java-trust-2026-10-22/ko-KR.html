emSign 인증서 신뢰 위험

v1.14.2 및 이전 버전 사용자는 외부 HTTPS 통신 가로채기와 Cookie 등 민감한 데이터 유출 위험을 줄이기 위해 즉시 v1.14.3 이상으로 업데이트해 주세요.

영향 범위

v1.14.2 및 이전 버전 사용자는 모두 업데이트해야 합니다. 실제 사용하는 Java 런타임이나 신뢰 저장소가 영향을 받는 인증서 체인을 계속 신뢰하면 프로그램의 외부 TLS/HTTPS 통신에 위험이 있습니다. Windows 설치 파일과 포터블 패키지에 포함된 Java도 해당합니다. 별도로 설치한 Java나 사용자 지정 신뢰 저장소도 확인해야 합니다.

보안 위험

일부 eMudhra / emSign 중간 CA의 개인 키가 매우 취약해 공격자가 임의의 웹사이트를 사칭하는 신뢰할 수 있는 인증서를 위조할 수 있습니다. 트래픽을 가로챌 수 있는 공격자는 영향을 받는 신뢰 저장소를 사용하는 모든 외부 HTTPS 연결을 탈취하거나 도청·변조할 수 있습니다. 원래 emSign 인증서를 사용하는 웹사이트에만 한정되지 않습니다.

요청에 포함된 Cookie, 액세스 토큰, API Key, 사용자 콘텐츠가 유출되어 계정 보안이 위협받을 수 있습니다. 브라우저, 시스템 구성 요소, 외부 도구는 각자의 신뢰 체계를 사용하므로 별도로 확인해야 합니다. 이 위험이 모든 프로토콜이나 연결이 이미 침해되었다거나 로컬에 저장된 데이터가 직접 읽혔다는 뜻은 아닙니다.

즉시 업데이트해 주세요

프로젝트 Release 페이지나 프로그램의 내장 업데이트 확인 등 공식 업데이트 경로를 통해 반드시 즉시 v1.14.3 이상으로 업데이트해 주세요. 설치를 완료하고 프로그램을 다시 시작하여 프로그램이 저장하고 네트워크 요청에 사용하는 Cookie 등 민감한 데이터를 보호해 주세요.

v1.14.3 Windows 설치 파일과 Java가 포함된 포터블 패키지는 emSign ECC Root CA - G3 신뢰 루트를 제거하고 문제가 있는 인증서 체인을 검사합니다. 이 루트에 의존하는 정상 HTTPS 서비스도 거부됩니다. Java ZIP, 별도로 설치한 Java, 사용자 지정 trustStore를 사용하는 경우 실제 사용하는 런타임이나 신뢰 저장소도 업데이트해야 합니다. 프로그램 JAR만 교체하거나 시스템 Java 또는 Windows 인증서 저장소만 업데이트해서는 내장 런타임이 교체되지 않습니다.

업데이트를 마칠 때까지 민감한 데이터를 다루는 네트워크 작업을 중단해 주세요. 인증서나 호스트 이름 검증을 끄지 마세요. Cookie 등 자격 증명의 유출이 의심되면 해당 서비스에서 세션이나 자격 증명을 폐기하고 새로 발급받으세요. 프로그램을 업데이트해도 이미 유출된 데이터를 회수할 수는 없습니다.
