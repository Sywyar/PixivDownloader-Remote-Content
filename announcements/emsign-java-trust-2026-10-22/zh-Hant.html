emSign 憑證信任風險

v1.14.2 及以前版本的使用者請立即更新至 v1.14.3 及以上，降低對外 HTTPS 通訊遭劫持及 Cookie 等敏感資料外洩的風險。

影響範圍

v1.14.2 及以前版本的使用者均應升級。若實際使用的 Java 執行環境或信任庫仍信任受影響的憑證鏈，程式的對外 TLS/HTTPS 通訊便有風險，包括 Windows 安裝程式與可攜版內建的 Java。自備 Java 或自訂信任庫也需要個別檢查。

安全風險

eMudhra / emSign 的部分中繼 CA 私密金鑰過弱，攻擊者可據此為任意網站偽造受信任的憑證。只要攻擊者能攔截流量，所有使用受影響信任庫的對外 HTTPS 連線都可能遭劫持、監聽或竄改，不限於原本使用 emSign 憑證的網站。

這可能洩露請求中攜帶的 Cookie、存取權杖、API Key 及使用者內容，進而危及帳號安全。瀏覽器、系統元件或外部工具使用各自的信任機制，需要個別判斷；此風險不代表所有協定或每次連線都已遭入侵，也不等於本機儲存的資料已被直接讀取。

請立即更新

請您務必立刻透過專案 Release 發布頁、軟體內建的「檢查更新」等入口，將程式更新至 v1.14.3 及以上，並完成安裝、重新啟動程式，以保護程式儲存並在連線請求中使用的 Cookie 等敏感資料。

v1.14.3 的 Windows 安裝程式及含內建 Java 的可攜版移除了 emSign ECC Root CA - G3 信任根，並加入問題憑證鏈檢查。依賴該根的正常 HTTPS 服務也會不再受信任。使用 Java ZIP、自備 Java 或自訂 trustStore 的使用者，還須更新實際使用的執行環境或信任庫；僅替換程式 JAR、更新系統 Java 或 Windows 憑證庫，無法取代內建執行環境更新。

更新完成前請暫停涉及敏感資料的連線操作，不要關閉憑證或主機名稱驗證。若懷疑 Cookie 等憑據已外洩，應在對應服務中撤銷工作階段或憑據並重新取得；更新程式無法收回已外洩的資料。
