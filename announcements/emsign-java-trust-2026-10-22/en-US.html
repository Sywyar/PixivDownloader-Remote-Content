emSign certificate trust risk

Users of v1.14.2 and earlier should update immediately to v1.14.3 or later to reduce the risk of intercepted outbound HTTPS traffic and exposure of cookies and other sensitive data.

Affected versions

All users of v1.14.2 and earlier should upgrade. Outbound TLS/HTTPS traffic is at risk when the Java runtime or trust store in use still trusts the affected chains. This includes Java bundled with Windows installers and portable packages. Separately installed Java runtimes and custom trust stores also need checking.

Security risk

Some eMudhra / emSign intermediate CA private keys were weak enough to let attackers forge trusted certificates for any website. An attacker who can intercept traffic may hijack, read or modify any outbound HTTPS connection that uses the affected trust store, including connections to sites whose genuine certificates were not issued by emSign.

This may expose cookies, access tokens, API keys and user content sent in requests, putting accounts at risk. Browsers, system components and external tools use their own trust mechanisms and must be assessed separately. The risk does not mean every protocol or connection has been compromised, or that locally stored data has been directly accessed.

Update immediately

Please update immediately to v1.14.3 or later through the project's Release page, the application's built-in update check or another official update entry point. Complete installation and restart the application to protect cookies and other sensitive data it stores and uses in network requests.

The v1.14.3 Windows installer and portable packages with bundled Java remove the emSign ECC Root CA - G3 trust anchor and add checks for the affected certificate chains. Legitimate HTTPS services that depend on this root will also be rejected. Users of the Java ZIP, separately installed Java or a custom trustStore must also update the runtime or trust store actually in use. Replacing only the application JAR, updating system Java or updating the Windows certificate store does not replace the bundled runtime.

Pause network operations involving sensitive data until the update is complete. Do not disable certificate or hostname verification. If you suspect credentials such as cookies have leaked, revoke the affected sessions or credentials with the service and obtain new ones. Updating the application cannot recover data already exposed.
