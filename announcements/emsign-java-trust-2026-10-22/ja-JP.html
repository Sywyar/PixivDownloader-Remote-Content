emSign 証明書の信頼に関するリスク

v1.14.2 以前をお使いの方は、送信する HTTPS 通信の乗っ取りや Cookie などの機密情報の漏えいリスクを減らすため、直ちに v1.14.3 以降へ更新してください。

影響範囲

v1.14.2 以前をお使いの方は更新してください。使用中の Java ランタイムやトラストストアが問題の証明書チェーンを信頼している場合、アプリケーションから外部への TLS/HTTPS 通信にリスクがあります。Windows インストーラーやポータブル版に同梱された Java も対象です。別途用意した Java や独自のトラストストアも確認が必要です。

セキュリティ上のリスク

eMudhra / emSign の一部の中間 CA では秘密鍵が非常に弱く、攻撃者が任意のサイトを装う信頼済み証明書を偽造できます。通信を傍受できる攻撃者は、影響を受けるトラストストアを使うすべての外向き HTTPS 接続を乗っ取り、盗聴、改ざんする可能性があります。正規の証明書が emSign 発行のサイトに限りません。

リクエストに含まれる Cookie、アクセストークン、API キー、ユーザーのコンテンツが漏えいし、アカウントの安全が損なわれるおそれがあります。ブラウザー、システムのコンポーネント、外部ツールはそれぞれの信頼機構を使うため、個別に確認が必要です。すべてのプロトコルや接続がすでに侵害されたこと、またはローカルに保存したデータが直接読み取られたことを意味するものではありません。

直ちに更新してください

プロジェクトの Release ページやアプリ内の更新確認など、公式の更新手段から、必ず直ちに v1.14.3 以降へ更新してください。インストールを完了してアプリケーションを再起動し、プログラムが保存してネットワークリクエストで使用する Cookie などの機密情報を保護してください。

v1.14.3 の Windows インストーラーと Java 同梱ポータブル版では、emSign ECC Root CA - G3 を信頼の起点から削除し、問題の証明書チェーンを検査します。このルートに依存する正常な HTTPS サービスも拒否されます。Java ZIP、別途用意した Java、独自の trustStore を使う場合は、実際に使用するランタイムやトラストストアも更新してください。アプリケーションの JAR だけを置き換えたり、システムの Java や Windows 証明書ストアを更新したりしても、同梱ランタイムの更新にはなりません。

更新が完了するまで、機密情報を扱うネットワーク操作を控えてください。証明書やホスト名の検証を無効にしないでください。Cookie などの認証情報が漏えいした疑いがある場合は、該当サービスでセッションや認証情報を失効させ、再取得してください。更新しても、すでに漏えいしたデータは取り戻せません。
